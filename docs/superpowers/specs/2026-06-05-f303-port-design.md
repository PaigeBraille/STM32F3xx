# STM32F303CCT6 port of Paige grblHAL firmware

Date: 2026-06-05
Status: approved

## Goal

Move the Paige firmware (currently grblHAL STM32F1xx, BTT SKR MINI E3 V2.0 derived,
STM32F103RC) to the grblHAL STM32F3xx driver targeting STM32F303CCT6 (48-pin, 256K
flash, 40K RAM). Identical pins and grbl settings for everything still in use.
Buildable and flashable with the existing PlatformIO + external UART-bootloader
programmer workflow.

## Scope

In:
- X/Y axes only (N_AXIS=3 required by core; Z mapped to dummy pins, no hardware)
- TMC2209 UART control on USART2 PA2/PA3 (TRINAMIC_STREAM 1, driver mask 0x03,
  StealthChop)
- X limit PB6, Y limit PB7
- Steppers: X step PB13 / dir PB12 / en PB14, Y step PB10 / dir PB2 / en PB11
- Main serial USART1 PA9/PA10 at 115200 (also the flashing UART)
- All non-default grbl settings carried over as DEFAULT_* build flags
- Flash NVS (FLASH_ENABLE=1), no EEPROM, no SD card, no USB CDC

Out (dropped per user):
- Electromagnet PWM module (M100-M102), retraction sensor + M103 (PC3 absent on
  48-pin package), Paige version report
- Z axis hardware (old Z pins PC5/PC2 absent on 48-pin package)
- Spindle, coolant, probe, control inputs - all already disabled on F1

## Approach

Build on the official grblHAL/STM32F3xx driver (cloned here). Its grbl core
submodule is current (newer than the F1 repo's). Work items:

1. Add `motors` and `trinamic` submodules (same upstreams as F1 repo)
2. New board map `boards/btt_skr_mini_e3_2.0_map.h` for F303: pins above; dummy
   Z = step PB0, enable PB1, dir PB5, limit PC13
3. Port `boards/btt_skr_mini_e3_2.0.c` TMC2209 UART glue (stream based, includes
   half-duplex hi-Z fix from F1 commit 539e556)
4. Rework `Src/serial.c`: replace hardcoded USART3 PB10/PB11 (conflicts with Y
   step) with F1-style SERIAL_PORT/SERIAL1_PORT selection - USART1 main, USART2
   second (F3 registers ISR/TDR/RDR, GPIO AF7)
5. Wire board into `Inc/driver.h`, verify trinamic init via core plugins_init
6. `platformio.ini` with env `BTT_SKR_MINI_E3_V20` (name kept so existing build
   habits work), F303CC board, linker script `STM32F303CCTX_FLASH.ld`, firmware
   at 0x08000000 with no vector offset (same programmer flow: BOOT0=1, reset,
   flash via USART1 ROM bootloader, BOOT0=0, reset)

## Verification

- `pio run -e BTT_SKR_MINI_E3_V20` builds clean, firmware.bin produced
- On hardware (user): $I reports board, TMC2209 responds (no driver fault on
  boot report), $HX homes X, G0 moves X/Y
